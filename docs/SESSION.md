## (2026-07-09) — WB bulk chars: скорость отправки cards/update

**Проблема:** первая пачка уходит быстро, дальше ~10 товаров/мин.

**Причина:** при ошибке пачки (400/429) код откатывался на отправку **по одной карточке** (~3 с на штуку); лимитер мутаций был слишком агрессивным (21 req/min) → 429 от WB.

**Исправлено:** пачки по **300** карточек; при ошибке — **деление пополам**, не поштучно; лимитер ~10 req/min; схемы категорий грузятся один раз (без дубля и sleep 0.55 с).

**Ожидание:** ~300 карточек / ~6 с ≈ **3000/мин** при успешных пачках (лимит WB ~10 запросов/мин × до 3000 карточек/запрос).

---

**Вопрос:** почему при массовом редактировании снова качается каталог с WB, хотя на диске уже есть.

**Ответ:** каталог хранится в SQLite (`packaging_dims_cards` в `data/reviews.db`), общий с панелью «Габариты». Повторная загрузка с WB происходит если:
1. Включена галочка **«Обновить каталог с WB»** (`force_refresh` — кэш очищается).
2. Кэш ещё не создан для этого магазина (ни разу не грузили «Габариты» / весь каталог).
3. Кэш старше 24 ч (`packaging_dims_cache_is_fresh`).
4. Кэш неполный (`truncated` или не `full_catalog`).

**UX:** без галочки прогресс показывает «Каталог из кэша (N карточек)»; в отчёте — «каталог из кэша» / «загружен с WB».
