## Критические / исправленные недавно

### BUG-00C: Таймаут соединения с WB обрывал операцию по всему магазину
- **Статус:** `fixed` (2026-09-08)
- **Симптом:** на Render в отчёте по магазину одна строка `Connection timeout to host https://content-api.wildberries.ru/content/v2/cards/update` (или `/object/charcs/{id}`) вместо построчного результата; остальные карточки не отправлялись
- **Причина:** `aiohttp.ServerTimeoutError` на connect (было 15 с). `wb_content_client._request_raw` ретраил только `HttpStatusError` — сетевые исключения не перехватывались (единственный клиент без `net.retry`); в `wb_certificates` строки и charcs ловят только `HttpStatusError`, поэтому ошибка вылетала наверх
- **Файлы:** `net.py` (`RETRYABLE_NETWORK_ERRORS`, `NetworkUnavailableError` = 504), `wb_content_client.py` (ретраи сети, `connect=30`, частичный каталог), `wb_certificates.py` (`_map_from_own_cards`)
- **Проверка:** локальный сервер с обрывами — успех на 3-й попытке; таймаут на одной карточке даёт «отправлено 2 из 3», а не падение магазина
- **Осталось:** при систематических таймаутах с Render нужен прокси в РФ (`WB_PROXY_URL`) или локальный запуск

### BUG-00A: Дата начала декларации не загружалась на WB
- **Статус:** `fixed` (2026-09-07)
- **Симптом:** номер декларации и дата окончания записываются в карточку, дата начала (регистрации) пустая или неверная; в разных категориях по-разному
- **Причина:** `_RE_DECL_REG_DATE` в `wb_certificates.py` совпадала с именем «Дата окончания действия декларации» через ветку `(дата|регистрац).*декларац`, а слоты `decl_*`/`cert_*` заполнялись без проверки «уже занято» → последнее совпадение (поле срока) перетирало найденную дату регистрации. В `_build_cert_patch_ids` `patches[cid]` затем перезаписывался датой окончания. Обратная регулярка срока в имя «Дата регистрации» не попадает — поэтому дата окончания всегда доезжала
- **Файл:** `app/core/wb_certificates.py` — `_charc_role` (срок раньше регистрации), `_assign_charc` (первое совпадение выигрывает, совмещённые имена → оба слота), guard в `_build_cert_patch_ids`
- **Проверка:** «Документы» → WB → «Только проверить»: в колонке «Поля WB» должны быть и «дата рег.», и «действует до» с разными id

### BUG-00B: Загрузка документа «чужого» типа затирала поля категории
- **Статус:** `fixed` (2026-09-07)
- **Симптом:** в категории есть поля только декларации; загрузка сертификата ничего не записывала, но очищала номер и даты декларации
- **Причина:** `_build_cert_patch_ids` очищал поля противоположного типа безусловно, даже когда номер записать было некуда
- **Файл:** `app/core/wb_certificates.py` — очистка только при `wrote_number`; строка получает статус `no_fields`

### BUG-000: Каталог Ozon загружался только 1000 товаров
- **Статус:** `fixed` (2026-09-07)
- **Симптом:** в связках/аудите виден кусок каталога (1000 из 5771), «пропавшие» товары и одиночки
- **Причина:** `/v3/product/list` больше не возвращает `has_next`; в `list_products_all` цикл выходил после первой страницы
- **Файл:** `app/core/ozon_client.py` — пагинация теперь по `last_id`, пока страница полная
- **Проверка:** `fetch_ozon_catalog` без `offer_ids` → 5771 строк на OZON ES

## Открытые — функциональность

### BUG-010: Не все одиночные товары попадают в предложения связок
- **Статус:** `open` / `monitoring`
- **Симптом:** Пользователь видит одиночки в каталоге, но нет attach/new_link предложения
- **Известные причины:**
  1. Название не проходит `_titles_related_enough` / `_item_matches_group_attach`
  2. Разный `subject_id` / `parent_id` (WB) или `category_key` (Ozon)
  3. Целевая связка уже `MAX_LINK_ITEMS` (30)
  4. Для `new_link` нужно минимум 2 похожих одиночки в категории
  5. Товар без `subject_id` (WB) пропускается в `suggest_link_candidates`
- **Нужно:** конкретные nmID для воспроизведения
- **Файлы:** `card_links.py` — `suggest_attach_to_groups`, `suggest_link_candidates`

### BUG-011: Дублирование логики сортировки каталога
- **Статус:** `open`
- **Симптом:** Расхождение порядка при фильтрации на клиенте vs сырой ответ API
- **Файлы:** `sort_catalog_rows` (Python), `cardLinksSortCatalogRows` (JS)
- **Риск:** Регрессии при правке только одной стороны

### BUG-012: Progress bar без реального прогресса
- **Статус:** `open`
- **Симптом:** Indeterminate анимация при загрузке каталога WB (до N страниц API)
- **Ограничение:** Endpoint синхронный, нет streaming progress
- **Улучшение:** task-based catalog load с poll (см. TASKS T-011)

### BUG-039: WB каталог не загружался при >1000 карточек
- **Статус:** `fixed` (2026-06-18)
- **Симптом:** «Загрузить» на вкладке Связки зависает или падает по таймауту на крупных магазинах WB
- **Причина:** O(n²) эвристики предложений (кластеризация по названию в одной категории) + долгая пагинация WB без reuse сессии; неверный критерий `cursor.total < 100` (total — размер всего кабинета)
- **Файлы:** `wb_content_client.py`, `card_links.py`, `server.py`, `app.js`
- **Проверка:** магазин WB с 1500+ карточек, hard refresh `app.js?v=45`
